# 低レベルのシステムソフトウェアを扱う

Modalix イメージ用の BSP ソフトウェアを準備するシステムエンジニア向けのガイドです。Palette SDK のツールチェーンでカーネルやデバイスツリーを扱い、PIB でリリース互換のパッケージをイメージに組み込みます。アプリケーション API と開発チュートリアルは [developer.sima.ai/software](https://developer.sima.ai/software) を参照してください。

## 互換性のある BSP リリースから始める

対象プラットフォームのリリースと一致するベンダーソースのリビジョンと設定を使用します。リポジトリの既定ブランチが、保守しているイメージのソースとは限りません。ソースリビジョン、設定変更、パッケージバージョンをリリース記録に残してください。

以下は ARM64 クロスツールチェーン環境を設定した Palette SDK コンテナ内で実行します。取得後、設定やビルドの前に対象リリースのリビジョンを選択してください。

## カーネルを設定してビルドする

```bash
git clone https://github.com/SiMa-ai/simaai-linux.git
cd simaai-linux
make ARCH=arm64 simaai_modalix_defconfig
make all -j8 ARCH=arm64 LOCALVERSION="-modalix" DTC_FLAGS=-@
```


カーネルイメージは `arch/arm64/boot/Image`、プラットフォームのデバイスツリーは `arch/arm64/boot/dts/simaai/` に生成されます。使用した設定とソースリビジョンを記録してください。

これらはビルド成果物であり、PIB 対応の完全なカーネルパッケージではありません。必要なブートファイル、パッケージスクリプト、リリース統合を維持するため、プラットフォームがサポートする Debian パッケージ作成手順を使用してください。

## デバイスツリーのオーバーレイをコンパイルする

```bash
dtc -@ -I dts -O dtb -o imx415.dtbo imx415.dtso
```


ファイル名を自分のオーバーレイに置き換えます。開発用ボードでハードウェアバインディングと周辺機器の動作を検証してください。対象リリースがサポートするブート設定に従って組み込みます。`.dtbo` をコピーするだけでは自動的に有効になりません。

## ブートチェーンの制約を理解する

カーネル、U-Boot、ATF、tRoot は互換性を維持する必要があります。現在の PIB では、カスタムカーネルはリリースのパッケージ名を維持し、唯一のインストール済みカーネルである必要があります。名前は `configs/images/image-params.yaml` で確認します。

PIB は tRoot、ATF、U-Boot のローカル置換パッケージを拒否します。イメージの U-Boot は `fip.bin` 内のコピーと一致する必要があります。`u-boot.bin` をビルドしても、ブートファームウェアの上書きが許可されたり、サポートされる手順になったりするわけではありません。変更はプラットフォーム供給元の復旧・署名プロセスに従って調整してください。

## PIB でシステム変更をパッケージ化する

リリース互換の ARM64 Debian パッケージを `custom-debs/` に置き、パッケージ署名情報で署名してイメージを作成します。

```bash
pib sign-debs
pib verify-debs
pib build --sign
pib verify
```


追加パッケージ名は `image.yaml`、設定は `overlay/`、サービス有効化など最後の変更はインストール後フックで指定します。カーネルとパッケージの規則は [PIB リファレンス](palette-image-builder-reference.md#customization)を参照してください。

マニフェストとチェックサムを保存し、復旧可能な開発用ボードで検証してください。変更に関係する周辺機器と更新・ロールバック動作も確認します。成果物のビルド成功だけではハードウェア互換性は確認できません。
