# Системний стек Palette SDK

Palette SDK надає інструменти для створення програмного забезпечення Modalix. Palette Image Builder (PIB) збирає це ПЗ у власний образ ОС eLxr. Це окремі контейнери: інструменти Palette SDK готують цільове ПЗ, а PIB складає образ пристрою. Посібник призначений для системних інженерів, які пакують образи та працюють із низькорівневим стеком. API застосунків і процеси їх розробки описані на [developer.sima.ai/software](https://developer.sima.ai/software).

## Де працюють компоненти

| Компонент | Місце виконання | Призначення |
|---|---|---|
| sima-cli | Ваш комп’ютер | Встановлює пакети, запускає та налаштовує середовище розробки |
| Контейнер Palette SDK | Docker на вашому комп’ютері | Кроскомпілює для ARM64 sysroot і надає інструменти розробки |
| Контейнер PIB | Docker на вашому комп’ютері | Створює кореневі файлові системи, пакети, образи дисків і підписані SWU за специфікацією образу |
| Modalix DevKit | Цільовий пристрій | Виконує застосунок ARM64 і встановлений образ eLxr |

SDK і PIB мають нативні контейнери x86 та ARM64. Docker автоматично вибирає варіант для хоста. Цільовий застосунок і образ пристрою залишаються ARM64. На хості x86 PIB автоматично використовує емуляцію ARM64 під час складання образу.

## Відкрийте інструменти системної розробки

Встановіть Palette SDK та налаштуйте середовище розробки системного ПЗ:

```bash
sima-cli neat install sdk@develop
sima-cli sdk setup
sima-cli sdk neat
```


Щоб під’єднати DevKit під час налаштування, вкажіть його адресу:

```bash
sima-cli sdk setup --devkit 192.0.2.10
```


Замініть приклад адресою свого DevKit. Підключення не обов’язкове для збирання, але корисне для розгортання й перевірки на обладнанні.

SDK містить інструменти кроскомпіляції, цільовий sysroot, заголовки, бібліотеки та допоміжні засоби. Робочу теку підключено в контейнері до `/workspace`, тому можна редагувати файли на комп’ютері та збирати в SDK.

## Підготуйте пакет для образу

Збирайте для Modalix ARM64 sysroot. Упакуйте результат і потрібні файли як пакет Debian з архітектурою `arm64`. Сценарії та інший незалежний від архітектури вміст можуть мати `all`.

Контейнер застосунку та образ операційної системи пристрою мають різне призначення. Створення Docker-образу застосунку не створює SWU й не замінює кореневу файлову систему eLxr на платі.

## Складіть образ пристрою через PIB

Встановіть PIB окремо:

```bash
sima-cli neat install sdk/pib
pib doctor
pib init my-image --flavor minimal
cd my-image
```


Проєкт поєднує:

- `image.yaml` для вибору варіанта, версії, пакетів і даних підписування.
- `custom-debs/` для підписаних пакетів ARM64 або незалежних від архітектури.
- `overlay/` для конфігурації та файлів, які в образі належать root.
- `hooks/` для змін після встановлення пакетів.
- `keys/` для даних підписування та публічних матеріалів довіри.

PIB завантажує пакети з налаштованих репозиторіїв і створює нову кореневу файлову систему. Він генерує підписаний `.swu` для оновлення та `.img.gz` для початкового запису диска або відновлення. Основний контейнер SDK не потрібно запускати.

Почніть із [повного прикладу власного образу](palette-image-builder-example.md), який поєднує пакування застосунку, службу та післяінсталяційний хук.

## Узгодьте версії інструментів, образу та плати

Платформний випуск контейнера визначає сумісні вхідні дані. PIB відхиляє проєкт іншого платформного випуску. Версія образу додає числовий номер збирання, наприклад `3.0.0.1`, і використовується політикою оновлення.

Зберігайте маніфест, SBOM, контрольні суми й дані підписування кожного випуску. Вони визначають відвантажений склад і дозволяють наступні оновлення під тим самим довіреним CA. Ключі підписування не вбудовані в опублікований контейнер збирання.
