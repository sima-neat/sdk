# Зберіть приклад власного образу

Цей посібник показує створення підписаного образу Modalix із невеликим застосунком, файлом конфігурації та службою, що запускається автоматично. Повний приклад входить до PIB: клонувати репозиторій чи встановлювати інструменти збирання на комп’ютер не потрібно. Цю саму специфікацію CI перевіряє на x86 та ARM64.

## 1. Встановіть і перевірте PIB

Встановіть sima-cli та запустіть Docker із рушієм Linux, а потім виконайте:

```bash
sima-cli neat install sdk/pib
pib --version
pib doctor
```


Якщо термінал не знаходить `pib`, відкрийте новий. У Bash або Zsh можна одразу оновити PATH:

```bash
export PATH="$HOME/.local/bin:$PATH"
```


PIB використовує власний контейнер x86 або ARM64. На x86 емулятор ARM64 налаштовується автоматично. Дозвольте привілейовані контейнери Docker та забезпечте щонайменше 10 GiB вільного місця і в каталозі проєкту, і в сховищі Docker для цього мінімального образу.

У Windows використовується власний засіб запуску та Docker у режимі контейнерів Linux. Модульні тести інсталятора Windows пройдені; повне створення образу через Docker Desktop/WSL2 ще не кваліфіковане. Наведені команди використовують синтаксис лапок Bash.

## 2. Скопіюйте приклад у проєкт

```bash
pib init my-custom-image --example custom-image
cd my-custom-image
```


Основні файли для налаштування:

| Файл | Призначення |
|---|---|
| `image.yaml` | Варіант, версія образу, пакети, накладання, хуки та підписування |
| `package-root/usr/bin/pib-example-app` | Застосунок із прикладу Debian-пакета |
| `package-root/DEBIAN/control` | Назва пакета, версія та архітектура |
| `overlay/etc/pib-example.conf` | Конфігурація застосунку для образу |
| `overlay/etc/systemd/system/pib-example.service` | Опис служби |
| `hooks/enable-example.sh` | Увімкнення служби та запис маркера збирання |

Щоб відкрити оболонку Linux у контейнері:

```bash
pib shell
```


Проєкт змонтовано в `/workspace`. Команда `exit` повертає на комп’ютер. Решту команд виконуйте на комп’ютері з каталогу проєкту: кожна команда `pib` автоматично запускає контейнер.

## 3. Створіть ключі розробника

```bash
pib keys init --cn 'My Company Development'
```


Команда створює CA, сертифікат і закритий ключ підписування SWU та ключі підписування власних Debian-пакетів. Після налаштування перемістіть `keys/ca.key` у захищене місце поза проєктом. Зберігайте той самий CA для оновлення наявних плат. Для серійних образів використовуйте виробничий процес підписування своєї організації.

## 4. Створіть і підпишіть пакет застосунку

Зберіть пакет у PIB, підпишіть і перевірте його:

```bash
pib shell -c 'dpkg-deb --root-owner-group --build package-root custom-debs/pib-example-app_1.0.0_all.deb'
pib sign-debs
pib verify-debs
```


Застосунок є сценарієм оболонки, тому архітектура пакета — `all`. Скомпільований застосунок Modalix має бути зібраний для `arm64`, зазвичай за допомогою SDK. PIB приймає пакети ARM64 або незалежні від архітектури; він не виконує крос-компіляцію вихідного коду застосунків.

## 5. Перегляньте специфікацію образу

Приклад містить такі налаштування:

```yaml
packages:
  add: [pib-example-app]
  remove: []
overlay: overlay
hooks: [hooks/enable-example.sh]
```


У списку вказують назву Debian-пакета, а не ім’я файла `.deb`. Змініть `overlay/etc/pib-example.conf` у редакторі, щоб спробувати власну конфігурацію. Хук вмикає службу після встановлення пакетів.

Версія образу складається з версії платформи контейнера та номера збирання, наприклад `3.0.0.1`. Для наступного образу збільшіть останнє число: плати застосовують політику заборони пониження версії.

## 6. Зберіть, підпишіть і перевірте образ

```bash
pib build --sign --supplier 'My Company'
pib verify
```


Перша команда створює нову кореневу файлову систему, встановлює застосунок, застосовує накладання та хук, створює артефакти, підписує SWU й перевіряє його. Друга показує окрему перевірку за допомогою CA проєкту та суміжного маніфесту збирання.

## 7. Знайдіть результати

Відкрийте каталог `out/` проєкту:

| Результат | Використання |
|---|---|
| `*.swu` | Підписане оновлення для працюючої плати |
| `*.img.gz` | Повний образ диска для початкового встановлення або відновлення |
| `*.manifest.json` | Версії та джерела встановлених пакетів, ідентифікатор збирання |
| `*.cdx.json` | Перелік програмних компонентів |
| `SHA256SUMS` | Контрольні суми артефактів |

SWU та повний образ диска — різні формати розгортання. Для встановлення SWU й початкової довіри до CA дивіться [довідник оновлення плати](palette-image-builder-reference.md#installing-an-swu). Для повного образу використовуйте процедуру підготовки Modalix. Перед виробничим використанням перевірте образ на платі розробника.

## 8. Замініть приклад власним застосунком

Зберіть застосунок як Debian-пакет ARM64 за допомогою SDK, помістіть його в `custom-debs/` та додайте назву пакета до `image.yaml`. Оновіть конфігурацію, службу й хук, потім повторіть підписування пакетів і створення образу. Ролі SDK, PIB та DevKit описано в [посібнику з архітектури SDK](sdk-architecture.md).

## Швидші повторні збирання

PIB використовує pigz для паралельного стиснення, сумісного з gzip. Щоб повторно використовувати перевірені завантаження пакетів:

```bash
export PIB_DEB_CACHE="$HOME/.cache/sima/pib-debs"
pib build --sign
```


Підписи репозиторіїв і хеші пакетів перевіряються під час кожного збирання. Заповнений кеш не замінює кореневу файлову систему та не пропускає встановлення пакетів, хуки, підписування чи перевірку.
