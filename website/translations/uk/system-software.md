# Робота з низькорівневим системним ПЗ

Цей посібник призначений для системних інженерів, які готують BSP для образу Modalix. Працюйте з вихідним кодом ядра й дерев пристроїв за допомогою Palette SDK, а потім використовуйте PIB для складання сумісних із випуском пакетів в образ. API застосунків і навчальні матеріали доступні на [developer.sima.ai/software](https://developer.sima.ai/software).

## Почніть із сумісного випуску BSP

Використовуйте ревізію вихідного коду та конфігурацію постачальника, що відповідають цільовій версії платформи. Типова гілка репозиторію не обов’язково відповідає образу, який ви підтримуєте. Зберігайте ревізії, зміни конфігурації та версії пакетів у документації випуску.

Виконуйте команди збирання в контейнері Palette SDK із налаштованим середовищем крос-компіляції ARM64. Нижче показано отримання коду; перед налаштуванням і збиранням виберіть відповідну ревізію випуску.

## Налаштуйте та зберіть ядро

```bash
git clone https://github.com/SiMa-ai/simaai-linux.git
cd simaai-linux
make ARCH=arm64 simaai_modalix_defconfig
make all -j8 ARCH=arm64 LOCALVERSION="-modalix" DTC_FLAGS=-@
```


Образ ядра створюється в `arch/arm64/boot/Image`, а дерева пристроїв платформи — у `arch/arm64/boot/dts/simaai/`. Зафіксуйте використані конфігурацію та ревізію коду.

Це результати компіляції, а не повний пакет ядра для PIB. Використовуйте підтримуваний платформою процес створення Debian-пакетів, щоб зберегти потрібні файли завантаження, сценарії пакетів та інтеграцію з випуском.

## Скомпілюйте накладання дерева пристроїв

```bash
dtc -@ -I dts -O dtb -o imx415.dtbo imx415.dtso
```


Замініть імена файлів своїми. Перевірте апаратні прив’язки й роботу периферії на платі розробника. Пакуйте або встановлюйте накладання через підтримувану конфігурацію завантаження вашого випуску: саме копіювання `.dtbo` не вмикає його автоматично.

## Врахуйте межі змін ланцюжка завантаження

Компоненти ядра, U-Boot, ATF і tRoot в образі мають залишатися сумісними. У поточному процесі PIB власне ядро має зберігати назву пакета ядра випуску та бути єдиним установленим ядром. Назву наведено в `configs/images/image-params.yaml`.

PIB відхиляє локальні пакети заміни tRoot, ATF і U-Boot. U-Boot в образі має відповідати копії у `fip.bin`. Збирання `u-boot.bin` не є дозволом або підтримуваною процедурою перезапису завантажувальної прошивки. Узгоджуйте такі зміни з постачальником платформи та його процесом відновлення й підписування.

## Запакуйте системні зміни за допомогою PIB

Помістіть сумісні Debian-пакети ARM64 у `custom-debs/`, підпишіть їх своїм ключем пакетів і зберіть образ:

```bash
pib sign-debs
pib verify-debs
pib build --sign
pib verify
```


У `image.yaml` перелічіть додаткові назви пакетів, у `overlay/` розмістіть конфігурацію, а в хуках після встановлення — увімкнення служб та завершальні зміни. Правила для ядра й пакетів наведено в [довіднику PIB](palette-image-builder-reference.md#customization).

Зберігайте маніфести та контрольні суми, тестуйте образ на платі розробника, яку можна відновити, і перевіряйте периферію та поведінку оновлення/відкату, на які вплинули зміни. Успішне створення артефактів не підтверджує апаратну сумісність.
