# Процес створення власного образу

Palette Image Builder (PIB), супутній інструмент Palette SDK, перетворює ваше ПЗ та системну конфігурацію на власний образ Modalix eLxr. Ця сторінка описує загальний процес. Повний приклад пакета, служби та накладання наведено в [прикладі образу](palette-image-builder-example.md).

## Встановлення PIB

Встановіть [sima-cli](https://docs.sima-neat.com/getting-started/installation), запустіть Docker із рушієм Linux, потім виконайте:

```bash
sima-cli neat install sdk/pib
```


Інсталятор вибирає власний контейнер x86_64 або ARM64, налаштовує засіб запуску й PATH та автоматично перевіряє хост Docker. Якщо PATH оновлено, відкрийте новий термінал. Для PIB не потрібен основний контейнер SDK.

Створення образу потребує привілейованого доступу Docker, підключення до репозиторіїв і вільного місця як у проєкті, так і в сховищі Docker: 10 GiB для `minimal` або 20 GiB для `palette`. На x86 PIB автоматично налаштовує емуляцію ARM64. Підтримку платформ, інші випуски та ручне встановлення описано в [довіднику зі встановлення](palette-image-builder-reference.md#installation).

## 1. Створіть проєкт образу

```bash
pib init my-image --flavor minimal
cd my-image
```


Виберіть варіант, сумісний із випуском платформи. Використовуйте `palette`, якщо потрібні робочий стіл та більший набір пакетів. Вибраний збирач надає типові параметри плати в `configs/`; зазвичай їх не змінюють. Наступні команди виконуйте з каталогу проєкту.

## 2. Визначте вміст образу

| Вхідні дані | Призначення |
|---|---|
| `image.yaml` | Варіант, випуск, версія образу, пакети й налаштування підписування |
| `custom-debs/` | Власні Debian-пакети ARM64 або незалежні від архітектури |
| `overlay/` | Конфігурація та файли для кореневої файлової системи |
| `hooks/` | Зміни після встановлення пакетів, зокрема ввімкнення служб |

Збирайте застосунки й компілюйте моделі за допомогою Palette SDK, а потім пакуйте потрібні цільовій системі файли. PIB складає пакети, але не компілює вихідний код застосунків. Ролі компонентів описано в [системному стеку Palette SDK](sdk-architecture.md). Винятком є ядро: `pib sbp` збирає його з публічного вихідного коду SiMa або з вашого у вигляді пакетів ядра в `custom-debs/`; див. [Збирання ядра](palette-image-builder-reference.md#building-the-kernel).

У `image.yaml` перелічіть назви Debian-пакетів, а не файлів `.deb`. Для файлів використовуйте накладання, для змін після встановлення — хуки. Докладні правила для пакетів, ядра й хуків наведено в [довіднику налаштування](palette-image-builder-reference.md#customization).

## 3. Підготуйте підписування й довіру

Для розробки один раз створіть ключі підписування проєкту:

```bash
pib keys init --cn 'My Company Development'
```


Після налаштування зберігайте закритий ключ CA офлайн. Для оновлення наявних плат використовуйте той самий CA, а для постачання — виробничу процедуру підписування організації. Зовнішні ключі, оновлення сертифікатів і розділення збирання та підписування описано в [довіднику підписування](palette-image-builder-reference.md#signing).

## 4. Налаштуйте вхід на плату

**Для входу через UART/консоль за паролем задайте `PIB_CREDENTIALS` перед збиранням.** Створення ключів підпису не задає паролів входу. Без цього файлу новий образ блокує паролі `root` і `sima`, тому вхід за паролем через консоль не працює, навіть якщо доступ за SSH-ключем працює.

У каталозі проєкту за допомогою OpenSSL на хості створіть захищений файл із хешами паролів. Введіть і підтвердьте пароль спочатку для `root`, потім для `sima`:

```bash
mkdir -p ../secure
chmod 700 ../secure
(umask 077; printf 'root:%s\nsima:%s\n' \
  "$(openssl passwd -6)" "$(openssl passwd -6)" > ../secure/credentials)
chmod 600 ../secure/credentials
export PIB_CREDENTIALS="$(cd ../secure && pwd)/credentials"
```

Зберігайте файл поза проєктом і системою контролю версій. Збирайте в тій самій оболонці; у новій оболонці знову експортуйте `PIB_CREDENTIALS`. PIB монтує файл лише для читання під час збирання.

Якщо потрібен лише доступ за SSH-ключем, файл можна не задавати, додавши схвалений відкритий ключ перед збиранням; див. [Доступ до плати](palette-image-builder-reference.md#board-access). SSH для root залишається лише за ключем навіть із заданим паролем. Після оновлення наявні плати можуть зберігати старі облікові дані в постійному оверлеї.

## 5. Зберіть і перевірте

Якщо проєкт містить власні Debian-пакети, підпишіть і перевірте їх до збирання образу:

```bash
pib sign-debs
pib verify-debs
pib build --sign
pib verify
```


Збирання створює нову кореневу файлову систему, застосовує вхідні дані проєкту, формує артефакти розгортання, підписує та перевіряє SWU. Результати, маніфест пакетів, SBOM і контрольні суми зберігаються в `out/`.

## 6. Розгорніть і підтримуйте

| Артефакт | Призначення |
|---|---|
| Підписаний `.swu` | Оновлення працюючої плати |
| `.img.gz` | Початкова підготовка диска або відновлення |

Перед розгортанням підготуйте доступ до плати й довіру до CA. Використовуйте процедури [доступу до плати](palette-image-builder-reference.md#board-access) та [встановлення SWU](palette-image-builder-reference.md#installing-an-swu). Успішне збирання не змінює та не кваліфікує плату.

Перевірте образ на апаратурі, яку можна відновити. Збережіть маніфести, контрольні суми та ключі підписування. Для наступних оновлень збільшуйте версію образу, а при зміні випуску платформи переносьте сумісні вхідні дані до нового проєкту. Дивіться [довідник оновлення платформи](palette-image-builder-reference.md#new-platform-release).

Завантажувальні розділи, слоти rootfs і розподіл тому даних описані в [розмітці носія та розділів](palette-image-builder-reference.md#media-and-partition-layout).
